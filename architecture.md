# Architecture

Each launch of `nook.exe`, or `nook` on Linux, is one process with one window. The window's tabs hold Claude sessions and open files. Rust owns processes and the disk. The webview owns everything you see. Started with `NOOK_WORKER` set, the same program is a sandboxed PDF worker instead (`sandbox.rs`).

Explorer's **Open with nook** on folders and folder backgrounds is two registry keys setup writes (`register` in `native/setup/src/main.rs`) and its uninstall deletes. Explorer starts `nook.exe "<folder>"`, and `dir_arg` in `main.rs` reads that argument.

## Host: `native/src/host`
One window around one webview, the page's calls into Rust, and the files the page loads, the same protocol on both systems. `mod.rs` holds `Config` and `run`.
- `ipc.rs`: the protocol. The page posts `[id, cmd, args]`, handled in the order posted, and hears `[id, 1, value]` or `[id, 0, error]`. An event is `[name, payload]`.
  - `cmd!` reads each argument by name through json.rs's `Take`. A `Run::Inline` command runs on the UI thread, in post order. A `Run::Thread` one runs on `work`'s workers: a waiting worker or a new thread, so a job never waits behind one that blocks. A worker leaves after 60 s idle.
  - `Stream` carries a channel's text, such as a terminal's output or git's progress. Pushes from any thread wake the UI thread once per burst, which posts whole UTF-8 characters in numbered pieces, then the end.
  - `builtin` holds the window's own `win_*` commands.
- `assets.rs`: what the page loads.
  - The page's origin is `http://tauri.localhost`, or `tauri://localhost` on Linux (`ORIGIN`).
  - App files come from `ASSETS`, every file of `dist/` compiled in, or in a debug build from the repository (`ROOT`), with `..` refused.
  - Files on disk are at `http://asset.localhost/<percent-encoded path>`, or `asset://localhost/` on Linux (`file`). A ranged answer carries at most 1000 KiB.
  - `/__ipc/<cmd>` runs a command that carries bytes (`FETCHED` in host.js), only for a POST whose Origin is the page's (`may_call`).
- `mime.rs`: MIME types by extension, for the page's files (build.rs uses it) and for files on disk.
- `dev.rs`: debug builds only. Polls what main.rs's `watch` names (`src`, `index.html`, `mod/themes`) every 100 ms. A changed stylesheet swaps in place, and any other change reloads the page.
- `win/`: Windows, through Win32 and WebView2 by hand-written COM (`com.rs`, `sys.rs`).
  - `mod.rs`: what goes to the page. A reply or event goes as a JSON string, which host.js parses, since a JSON web message would reach the page with each object's keys sorted. A reply or a stream's piece over 4 KiB (`SHORT`) goes as a shared buffer instead.
  - `window.rs`: the frameless top-level window. The system's shadow and its side and bottom resize edges come from a non-client inset, and a child strip over the webview resizes from the top. It stays hidden until the page loads, or 3 s. It runs the UI thread's message loop, which other threads reach through `post`.
  - `webview.rs`: the environment, the controller, the settings nook changes, and the events. NavigationStarting cancels any URL but nook's page in the main frame. WebMessageReceived takes calls only from nook's page. PermissionRequested allows `queryLocalFonts` for the font pickers. NewWindowRequested opens nothing.
  - `serve.rs`: WebResourceRequested, for every frame and worker. App files are answered inline from static memory. Files on disk and command fetches are answered on a worker.
  - `loader.rs`: finds the WebView2 runtime through EdgeUpdate's registry keys, or `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`, and starts an environment, as the SDK's WebView2Loader.dll does. `WEBVIEW2_USER_DATA_FOLDER` overrides the profile.
  - `drop.rs`: one OLE drop target on every window of the webview, so a file dropped anywhere on the page, frames included, reaches it as a `drop` event: `over`, `leave`, then `drop` with the paths, in CSS pixels.
- `gtk.rs`: Linux, through GTK 3 and WebKitGTK 4.1 (2.40 or later) by hand-written FFI.
  - An undecorated window that resizes from 5 px at each edge. A press on a drag region moves it.
  - Both URI schemes are registered secure and CORS-enabled. Calls come through the `ipc` script message handler. Replies, events, and stream text go through `__nook.receive(…)` and `__nook.text(…)`, and only while the main frame shows nook's page (`page_is_ours`). `load_changed` stops a load of anything else.
  - The desktop's light or dark comes from its settings portal. Drags from other apps arrive as `drop` events.
  - The GIO and D-Bus bindings `shell_unix.rs` and `notify.rs` use: `bus_call` (one synchronous call on the session bus, its reply handed to a reader), `lists` (whether a string-array reply names one), and `error_text` (a GError's message, freed).

## Rust: `native/src`
- `main.rs`: `main`, the command table, and the file commands.
  - `commands(name)` registers every command the page calls but the window's own, through `cmd!`, each as `Run::Inline` or `Run::Thread`.
  - Its own commands: `boot`, `settings`, `update_settings`, `list_dir`, `read_text`, `write_text`, `create_path`, `file_stamp`, `path_kinds`, `peek_lines`, and `bench`.
  - `file_stamp` is a file's modified time and size, plus the time of asking while the file is `fresh` (written in the last 2 s).
  - `resource(name)` finds what ships beside the program: beside nook.exe in a release build, or in the repository in a debug build.
  - `config_dir` (settings.json, theme.css, themes: `%APPDATA%\<id>` or `~/.config/<id>`), `data_dir` (the webview's profile, localStorage included: `%LOCALAPPDATA%\<id>` or `~/.local/share/<id>`), and `cache_dir` (the baked backdrops: `%LOCALAPPDATA%\<id>` or `~/.cache/<id>`). `<id>` is the build's `NOOK_ID`.
  - `run` runs a console tool and returns its output, and `spawning` starts processes one at a time.
- `settings.rs`: what settings.json holds, its defaults, and its JSON (`settings!`, keys written in field order). main.rs reads and writes the file (`read_settings`, `edit_settings`).
- `json.rs`: nook's JSON. `parse` builds a `J` tree, `Reader` and `Take` read typed values straight off the text, `fields` picks keys, and `W`, `obj!`, and `object!` write.
- `pty.rs`: one console (a pseudoterminal on Linux) per Claude tab, keyed by the id `pty_spawn` returns.
  - `pty_spawn` sets `TERM`, `COLORTERM`, `FORCE_HYPERLINK` (so Claude sends OSC 8 links), and `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` (so Claude draws a mod's `Image` as kitty graphics, which it otherwise does only in kitty and Ghostty).
  - It also sets `CLAUDE_CODE_PLUGIN_DIRS` (nook's mod after the user's plugins, without the mod of a nook it was started from), `NOOK_STATE` (the session's report file, `nook\<pid>-<id>.json` in the temp folder, from `state_file`), `NOOK_CLAUDE_TEMP` (Claude Code's temp folder, from `claude_temp`), and `CLAUDE_CODE_SSE_PORT` (ide.rs).
  - Programs' output goes into a host `Stream` (`Pty::output`): from the console's thread on Windows, from a reader thread on Linux. A writer thread per session writes its keys and applies its sizes in the order they came, so a program that stops reading holds up only its own tab, and ticks the console when its wait for the terminal's cursor answer is up (`due`, `tick`). When the shell exits, the stream ends and the tab closes. `close_all` returns each session's end, which `main` joins before nook exits.
  - `pty_states` reads every listed tab's report in one call. `pty_command` leaves a request for the mod in the `.cmd` file beside the report. `session_image` finds `[Image #N]` in the folder the report names.
- `pty_windows.rs`: a tab's console (`console`) and the process started in it, which CreateProcess attaches to the console through its pseudoconsole attribute, with no pipes. The process gets the environment a new login would: Windows' variables read fresh from the registry, with the session's over them.
- `console/` (Windows): nook's console server, one per tab on a thread of its own, speaking the console driver's protocol (`\Device\ConDrv`) as OpenConsole does.
  - `mod.rs`: the driver's calls, the IO loop (`serve`), `Console` (open, write, resize, close), and control events: user32's ConsoleControl, else kernelbase's CtrlRoutine run in the process.
  - `api.rs`: the console's state and every message. Output goes to the tab as written, VT and kitty graphics and sixel included, and legacy colors as SGR.
  - `cells.rs` and `screen.rs`: the APIs that read or change cells in place, answered from a cell buffer that only the output fills.
  - `cooked.rs`: line editing for cooked reads (cmd's, Python's): insert mode, each program's history, and Tab completion. `input.rs`: the terminal's keys as input records. `window.rs`: the hidden window GetConsoleWindow returns.
  - `wcwidth.rs`: cell widths from `src/term/wcwidth.js`'s tables, read at build time.
- `pty_unix.rs`: a Linux pseudoterminal from `/dev/ptmx`, through the few libc calls std doesn't wrap.
- `ide.rs`: each Claude tab is its Claude's IDE: a WebSocket on 127.0.0.1 behind a random token, which Claude finds through `CLAUDE_CODE_SSE_PORT` and `~/.claude/ide/<port>.lock`.
  - It tells Claude the file shown last and the lines picked in it (`ide_selection`). An edit Claude asks a yes for (`openDiff`) opens as a proposal tab, whose Accept or Reject answers Claude (`ide_diff_answer`).
  - `sweep`, on its own thread at start, deletes the report and request files of nooks that no longer run.
- `git.rs`: the git panel's commands. Each runs the git CLI, so hooks, signing, and credential helpers behave as in a terminal, with no prompt to hang on (`GIT_TERMINAL_PROMPT=0`, `GIT_EDITOR=:`).
  - `git_status` finds the repository above any path and reads its status, line counts, and remotes in parallel.
  - `git_diff` returns the staged or the unstaged changes as a unified diff, with untracked files written as git would diff them once added, so a patch of some of their lines stages them.
  - `git_progress` runs a fetch, pull, or push and streams git's progress lines to a channel. `git` runs any other command.
- `shell.rs`: hands paths to the Windows shell.
  - `open_path` runs a verb on a path: open, Open with, or Properties. `reveal` runs `explorer /select,`.
  - `recycle`, `rename_path`, `paste_files`, and `drop_files` run `SHFileOperationW`, so Explorer's progress, conflict, and error dialogs show and Explorer can undo each change. Each runs on a worker with no owner window, since a dialog that owned nook's window would disable it.
  - `copy_files`, `paste_files`, and `copied_paths` use the clipboard format Explorer uses for files, so a copy pastes in either app.
- `shell_unix.rs`: the same commands on Linux, through GIO and D-Bus.
  - `open_path` launches the default app for a `file://` URI, or a URL as given (`g_app_info_launch_default_for_uri`). A folder goes to the file manager's `ShowFolders` first. `reveal` asks `ShowItems` to select the file, or else opens its folder. Both are Inline, so each runs on a thread of its own.
  - `recycle` calls `g_file_trash`, and fails where there's no trash.
  - Rename and moves use `renameat2` with `RENAME_NOREPLACE`, and check then rename only where the file system refuses the flag. A paste's copy creates each file only if its name is still free.
  - Desktops share no file clipboard the way Explorer's apps do, so Cut, Copy, and Paste keep nook's own, and a paste names a copy beside its original as Explorer does.
- `theme.rs`: themes.
  - `read_theme(seen)` returns the user's `theme.css`, the installed theme `settings.json` names with its `theme.css`, and a `stamp` that changes when a file beside either does. It answers null while its `version`, a hash of the files' stats alone, still equals `seen` and no file it reads is fresh. It parses settings.json again only when its stats change or it's fresh.
  - `stamp` hashes each entry's modified time and size, and on Linux its change time, since a copy keeps its source's modified time.
  - `install_theme` takes a folder or a .zip on disk, `install_theme_zip` a .zip the drawer picked, as bytes, and `install_theme_files` a theme the page made (from a picture). Each goes through `install`, into a hidden folder in `themes`, then swaps in with two renames.
  - `save_theme_zip(name)` zips a theme's folder into Downloads, as `<name>.zip`, or `<name> (2).zip` on. `zip_holds_theme` says whether a .zip holds a theme.css, at its top or in one folder.
  - `offer_bundled` copies in the themes that ship beside nook (`resource("themes")`): all on the first run, and on a later start, after 5 s, the ones a newer nook added.
  - `save_backdrop` and `saved_backdrop` keep backdrops.js's bitmaps in `cache_dir`.
- `zip.rs`: zip archives, std alone. It reads an archive's index from its tail, unpacks stored and deflated entries and checks each one's CRC-32, and writes archives that store each file as it is. It refuses the whole archive for a name that is absolute, on a drive, through `..` or a part of only dots and spaces, or holding `:`. It also refuses entries that share bytes, more than 4096 files or 256 MB (unpacked or packed, whichever is more), zip64, and encryption. A name without the UTF-8 flag that isn't UTF-8 reads as CP437.
- `pdf.rs`: a PDF's first page as a PNG, for its picture in the transcript. `pdf_page` reads the file (256 MiB at most) and hands its bytes to a worker. `answer`, the worker's side, draws with the OS: on Windows, Windows.Data.Pdf on a software Direct3D device, encoded by WIC, and on Linux poppler-glib, loaded with `dlopen`, and cairo, so a system without poppler draws nothing. Neither runs the file's scripts, and both draw its annotations and form fields.
- `sandbox.rs`: the PDF workers: nook's own program started again with `NOOK_WORKER` and no other environment but, on Windows, `SystemRoot`. Each takes one request at a time, up to 4 run at once, over a pipe each way. A worker that dies, or doesn't answer within 10 s, fails that one page and is ended, and one idle for 60 s ends.
  - On Windows a worker runs in an AppContainer of its own (a random SID) with no capabilities and every privilege but one removed, so it reads none of the user's files and reaches no network. Its job lets it start no process, touch no other window or the clipboard, or use over 1 GiB, and ends it when nook's handle closes. It starts with `DETACHED_PROCESS`, so it has no console at all.
  - On Linux a worker sets no_new_privs. Where the kernel has Landlock (5.13 on, if enabled), it reads only beneath the system's folders. On x86-64 a seccomp filter refuses sockets, starting programs, writing files, and signalling other processes. Without Landlock, a compromised worker could read the user's files, though it can't send them anywhere but its answer.
- `index.rs`: quick open's file list: `git ls-files` inside a repository, or a breadth-first walk outside one, which stops after four seconds. Either stops at 200,000 files.
- `search.rs`: quick open's `%`: lines holding the text in quick open's file list. Up to eight threads read the files, skipping binaries and files over 2 MB, and stop at 300 lines or three seconds. A query with a capital letter matches case exactly. A newer search stops an older one.
- `find.rs`: the search tab's matcher. Literal text takes a fast path (`Needle`, SSE2 on x86-64). A regular expression has regex-lite's syntax and error texts and leftmost-first matches, run by a PikeVM in time linear in the text. Case folding, `\w`, `\d`, `\s`, and `\b` are ASCII only. `Filter` is the file filter's syntax.
- `replace.rs`: the search tab's `find_in_files` and `replace_in_files`, through find.rs. Up to eight threads read the files, skipping binaries, files that aren't UTF-8, and files over 2 MB, and stop at 5,000 matches or eight seconds. Each file comes back with a stamp of its bytes, and a replace rewrites, under `WRITING`, only files that still have it, keeping a BOM. `undo_replace` writes back what each file held, to each file still holding what the replace wrote.
- `defs.rs`: definitions, by a line scanner rather than a parser: the declarations each language family starts a line with (`fn`, `def`, `class`, `func`, a JavaScript `const f = () =>`, a C function's head, a Markdown heading), skipping strings and comments, and nested by braces or indentation.
  - `workspace_symbols` serves quick open's `#` and F12 across quick open's file list. Up to eight threads read files under 1 MB, and each file's definitions are kept with its modified time and size, so a second ask rereads only what changed. It stops at 200,000 definitions or five seconds.
  - `outline` serves `@` from a file tab's unsaved text, with outline-only kinds, at most 5,000 items, and UTF-16 columns.
- `history.rs`: `claude_sessions`, the saved sessions of a folder from Claude Code's transcripts in `~/.claude/projects`, reading each one's first prompt and last title only.
- `commands.rs`: `claude_commands`, the slash commands and skills Claude Code offers in a folder: `.claude/commands` and `.claude/skills` in the folder and its parents up to the git root, then `~/.claude`'s, each file's frontmatter only.
- `notify.rs`: a desktop notification for a session in the background: on Windows the notification area's balloon, which Windows shows as a toast, and on Linux `Notify` on the freedesktop notification service, with the body escaped where the server reads markup.
- `priority.rs`: every 2 s, sets above-normal priority on the typing path: nook, its WebView2 processes, the console host, the shell, and `claude.exe`. The walk stops at `claude.exe`, so the tools Claude runs keep normal priority. On Linux, `priority_unix.rs` does nothing, because raising a priority needs `CAP_SYS_NICE`.
- `sys.rs`: every Win32 function, struct, and constant nook calls, imported from the system DLLs as raw-dylib, with the structs' sizes asserted.
- `com.rs`: COM by hand, for the host and pdf.rs: `call!` through vtable slots, `Com`, `Guid`, and `handler`, the one callback object every WebView2 completion and event shares.

## Build, install, and notices
- `native/build.rs`: the build's identity (`rsrc::identity`), the exe's resources on Windows, and the page: `ROOT` in a debug build, or `ASSETS`, every file of `dist/` (the bundler's output, git-ignored), in a release build, which fails without `dist/index.html`.
- `native/rsrc.rs`: shared by nook's and setup's build scripts. `identity()` reads `NOOK_ID` (default `dev.nook.app`) and `NOOK_NAME` (default `nook`), which name the build's folders, window, and installer, and refuses a path, a wildcard, or a name of only dots, since setup's uninstall deletes what they name. `link` writes a COFF `.rsrc` that GNU ld and MSVC link.exe both take: icon group 32512, VERSIONINFO, and a manifest for Common Controls 6 and PerMonitorV2.
- `native/icons/icon.ico`: the one source of nook's raster icons: both exes' resources (rsrc.rs), the Linux window icon (main.rs), and the .deb's hicolor PNGs. `icon.svg` at the root is the .deb's scalable icon.
- `native/setup`: the Windows installer and its uninstaller, one `no_std` exe with no crates, in a cargo workspace of its own.
  - `setup --pack <stage> <out>` writes a copy of itself followed by an index of the stage's files, the files LZMS can't shrink as they are, the rest as one LZMS block, and a trailer with a CRC.
  - The installer is per user: `%LOCALAPPDATA%\<name>`, or `/D=`. `/S` is silent, and `/UPDATE` skips the WebView2 check. With `/UPDATE` or `/NS` it adds no Start menu shortcut, and a silent run adds a desktop one only on a first install without either.
  - It runs WebView2's bootstrapper when no runtime is registered, closes every process holding one of the payload's programs or libraries through the Restart Manager, forcing any that don't respond, writes the files, the Uninstall entry, the folder menu, and shortcuts carrying `NOOK_ID` as their AppUserModelID. An NSIS install it finds runs its own uninstaller first.
  - `uninstall.exe` is the same exe carrying the file list instead, and takes NSIS's `_?=`. Its "Delete app data" removes `%APPDATA%\<id>` and `%LOCALAPPDATA%\<id>`.
  - `src/main.rs` holds the flows, packing, files, registry, and shortcuts, `src/ui.rs` the task dialog, and `src/sys.rs` the Win32 calls, the heap, and the entry point.
- `scripts/build.mjs`: the build, with Node's own modules only.
  - In order: the page into `dist/` (`bundle`), nook through `cargo rustc --release` with `--remap-path-prefix=<home>=~` (and `+crt-static` on an MSVC host) after any flags the user set, the stage, then setup and `setup --pack`, or on Linux `deb()`. `--no-pack` stops at the stage, and `--dist` after `dist/`. It builds for the host toolchain, so an MSVC build takes an MSVC host (`RUSTUP_TOOLCHAIN`).
  - The stage, `native/target/release/stage`, is nook.exe and `PAYLOAD`, a nook that runs where it is. `PAYLOAD` is the one list of what ships beside nook.exe. The installer is `nook_<version>_x64-setup.exe` beside it, or on Linux `nook_<version>_<arch>.deb`.
  - It refuses `NOOK_NAME` without `NOOK_ID`, and `NOOK_ID` without `NOOK_NAME` when it packs.
  - `dist/` holds `index.html`, `index.css` (the stylesheets index.html links), `index.js` (every module main.js imports statically, the runtime `E`, `F`, and `J` first), and one chunk per set of `import()` targets, named for its root module. The files a `new URL('./f', import.meta.url)` or a stylesheet's `url()` names are copied in at their place under `src/`, except that a lazy stylesheet only one module adds, naming no other file, rides in its chunk as `data:text/css`. One that two modules add, as `diff.css` is, ships as its own file.
  - `parse` reads each module's imports, exports, and assets, and `mangle` renames locals by scope. `put` writes only bytes that changed, so cargo relinks nook.exe only when the page changed, and files an earlier build left go.
- `scripts/icons.mjs`: builds `src/fonts/nook-icons.woff2` with Node alone. `node scripts/icons.mjs` fetches the pinned `@fluentui/svg-icons` SVGs, and `node scripts/icons.mjs <folder>` reads them from a folder. `ICONS` maps each Segoe Fluent Icons code point to the Fluent UI System Icon that draws it.
- `LICENSES.txt`: every third-party notice, shipped beside nook.exe: the code nook ports (xterm.js's parser table, keyboard, and buffer reflow, and its web-links and unicode11 addons, in `src/term`, and marked's Markdown grammar, in `markdown.js`), Fluent UI System Icons, OpenConsole (which `native/src/console` follows), and the Libron font.

## Claude Code mod: `mod`
A plugin named `nook` that ships beside nook.exe and loads in every Claude session nook starts, beside the user's own plugins. `hooks/register.js` holds every hook, and every hook passes its event on. `types/index.d.ts` types what it keeps in `$.state`. `hooks/register.test.ts` checks its hooks under `claude plugin test mod`, and `claude plugin validate mod` lists everything it reads and calls. A tab nook started is one whose session has `NOOK_STATE` and draws on a surface.
- The report: in a tab nook started, the mod writes the session's state as JSON to `NOOK_STATE`.
  - The model, the `/model` aliases Claude offers among fable, opus, sonnet, and haiku (each its family's latest), the effort and its five levels, the context fill, the cost, the account's rate limits, the session id and root, and the pasted images' folder (`imagesDir`).
  - What the session is doing: `status` (working from `turn.start`, waiting while a permission prompt or a question to the user is up, idle from the main turn's `turn.complete`), `since`, the running tool as `activity`, what a permission prompt `asks`, the turn's first line as `prompt`, the reply's gist as `answer`, the subagents running, the turns finished, the task list's progress as `plan`, and `touched`, the files its Edit, Write, MultiEdit, and NotebookEdit calls wrote.
  - A Run or Review pressed in the transcript, which the composer acts on.
  - Every 250 ms it reads the model and usage again, so a switch made any way and a `/clear` show, and runs a request `pty_command` left in the `.cmd` file beside `NOOK_STATE`. A request runs only `/model` with one of the aliases or `/effort` with one of the five levels, through `$.command.run`, so the draft stays as typed.
- `prompt.compose`: in a tab nook started, one section added to Claude's system prompt (`DRAWS`), saying what nook draws in a reply and to use it only when it makes an answer clearer.
- `ui.render` `ToolUse`: a picture under a `Read` of an image or SVG and a `Write` of an SVG. In a tab nook started, also the first page of a PDF Claude reads, and the page under a finished `Write` of an `.html` or `.htm` file, laid out in a 1280 by 800 window (64 by 20 cells).
- `ui.render` `ToolResult`: under a shell command's result, how it went, read from the last 64 KB of its output: a test runner's own counts and the first three tests that failed, the line that names a failure's error with a Rust error's `-->` place, what a build, install, linter, or git command says it did, and how long a command past 3 s ran. Then up to three pictures it wrote, found once when it ends. Under a web search, how many results and the first three sites. Under an edit's diff, in a terminal, an Undo that applies the edit's hunks backward, and then a Redo.
- `ui.render` `ToolGroup`: under a run of calls Claude folds into one line, the files read (eight at most, so nook links each), what each search found (`Grep`, `Glob`, a web search, or a lone search command through `Bash`, such as `grep`, `rg`, or `find`), each finished command's outcome (six rows at most), and the pictures its calls read or wrote.
- `ui.render` `AssistantMessage`:
  - In a tab nook started, a ```` ```mermaid ```` block becomes a diagram in its place: the mod saves it as `diagram-<hash>.mmd` beside `NOOK_STATE` and names that file as an `Image`, its box guessed from the source. A display formula on lines of its own, `$$ … $$` or `\[ … \]`, becomes `math-<hash>.tex` the same way. An SVG block stays as source and its picture, `svg-<hash>.svg`, follows it.
  - In any terminal, an inline `$…$` is written in plain Unicode when all of it has a plain form, and a picture file a reply links with `![alt](path)` draws after its paragraph, four at most.
  - Under each code block, a Copy. In a tab nook started, a one-line shell block also gets a Run, which nook types into an empty prompt as a `!` command for the user to send.
  - `codeBlocks` is the one fence reader, by CommonMark's rules, and `displayMath` finds display formulas in one pass.
- `ui.render` `AbovePrompt`: after a turn that edited files, a band over the prompt: what changed, Review (in a tab nook started, nook opens those files' changes), Undo turn (a new file stays), and ✕.
- `ui.render` `UserMessage`: the pictures a prompt's `[Image #N]` names.
- A picture's size in cells comes from its pixel size, about 20 pixels a row and 20 rows at most, read from a PNG's, JPEG's, GIF's, or WebP's header, an SVG's viewBox, or a PDF's first `/MediaBox` (US letter when it's compressed away). The `ToolResult` and `ToolGroup` additions pass when the view is expanded, so ctrl+o shows Claude's own rows alone.
- `themes/nook.json` is a Claude theme, which `/theme` lists as nook and settings name `custom:nook:nook`. It draws each Claude color token it lists in its own palette slot from 16 up, on Claude's `dark-ansi` theme, so every other token takes one of the 16 ANSI colors.

## Frontend: `src`
A module reached only through `import()` loads the first time it's needed, as its bullet says. The rest open with the window. A `<module>.test.js` beside a module checks it under `npm test`, without a window.

### The window
- `index.html` is the window's markup: titlebar, file browser, pane, git panel, and settings drawer. Its `<link>` lines are the stylesheets the window opens with, and `<style id="pack">` and `<style id="theme">` come last in `<body>`.
- `host.js` is the one door to the native side: `invoke`, `Channel` (a stream's pieces put back in `seq` order), `listen`, `convertFileSrc`, and `win`. The commands in `FETCHED` go by fetch. Call and channel ids start at a random number per page, so what the host sends to a page before a reload finds nothing. A press on a `data-drag-region` sends `win_drag`, and a double press toggles maximize.
- `main.js` boots the window: settings, theme, file browser, git panel, tabs, wallpaper, and titlebar.
  - Dragging a panel's edge sets `--files-width` or `--git-width` on `body` and saves it to settings.json. A double-click on the edge restores the theme's `--sidebar-width`. Each restyle sets the window's background to the theme's `--bg`, which shows while a growing window repaints.
  - It takes the window's keys before Claude or the editor can: Ctrl+P, F1, and Ctrl+Shift+O (quick open), F12, Ctrl+T, and Alt+Left (definitions), Ctrl+Shift+P (quick prompts), Ctrl+Shift+S (the dashboard), Ctrl+Shift+E (the file list), Ctrl+Shift+H and Ctrl+Shift+F outside a Claude tab (the search tab), and F11 (focus mode: Claude alone in a column over the wallpaper).
  - The chevron beside + starts Claude other ways: continuing the folder's last session, resuming a saved one, or in a git worktree of its own (`claude --worktree`). `fanOut` sends one prompt to several new sessions, each in a worktree.
  - A file dropped from the OS becomes a path in the prompt, or a copy in the folder under the pointer.
  - The welcome (`welcome.js`) loads and shows on the first run, once Claude's tab is up, and from the command palette after.
- `ui.js` holds `$`, `el`, `flag(key, fallback)` (the localStorage switches: diff split, history scope, blame), `letter(e)` (the one rule for a Ctrl or Alt letter shortcut outside the editor, which uses `keyName` in edits.js), and the floating pieces: context menu, filtered picker, image preview, and drag ghost. A menu item that is itself a list of items renders as a row of icon buttons. `sheet(url)` adds a lazily loaded view's stylesheet, awaited at the top of the view's module, once per address.
- `paths.js` holds what differs between Windows and Linux paths: the separator, roots, case, and which characters a name can't hold. Every module builds and compares paths through it. `WINDOWS` also picks the image-paste key, Alt+V on Windows and Ctrl+V on Linux.
- `tabs.js` owns the tab strip and the pane under it. A tab is a Claude session, an open file, a diff, a review of a turn's changes, a merge, a stash, a history, the search tab, or an edit Claude proposes (`proposal.js`).
  - Closing a file with unsaved edits, or the window that holds one, asks whether to save. The window closes with its last tab. Every 2 s it refreshes the active tab, so a file tab rereads its file's stamp.
  - Ctrl+\ or a tab's **Open beside** splits the pane: the active tab keeps the focused half and the other shows in the other half, marked beside in the strip. A click in a half focuses it, a tab picked from the strip takes the focused half's place, and the divider drags.
  - It saves the Claude sessions open now (folder, session id, first prompt, which one showed) to settings.json's `sessions` as they change. The next start, unless it was asked for a folder or `reopenSessions` is false, reopens them as tabs that run `claude --resume <id>`. Only the tab that showed starts, and each other one starts when it's first shown.
  - A session that moves, as into its worktree, reports its new root, and its tab takes the worktree's name and its git panel follows. Prompts queued for a session go once its turn ends.
  - It tells ide.rs which file showed last and the lines picked in it.
- `sessions.js` follows every Claude tab's session. `watchSessions` reads the tabs' reports in one `pty_states` call: the tabs in view every 500 ms, so a composer's menus follow a pick, and the rest each second. It hands each changed report to tabs.js, which hands it to the tab's terminal and its composer. `follow` turns a report into the tab's mark: working, waiting on the user, or done, a turn that finished while the user looked elsewhere. A tab's dot shows its mark in its icon's place, the window's title counts the sessions waiting or done, and a session that starts waiting or finishes unwatched asks the taskbar for attention once, and with nook in the background shows a desktop notification (`notifications` in settings.json).
- `dashboard.js` (and `dashboard.css`) is the sessions dashboard, over the pane. It loads on its first open, from the titlebar's button or Ctrl+Shift+S, or as the pointer reaches the button. Its header comment lists what a card shows and does: allow or deny a permission prompt, compact a session, keep or discard a worktree's changes (`keep.js`), and one prompt to several sessions, queued or in new worktrees.
- `launch.js` holds the chevron's helpers. `claudeWith` adds Claude's flags to settings.json's command and refuses anything but names and ids. `history.rs`'s `claude_sessions` lists what Resume offers.
- `prompts.js` is quick prompts' logic, for main.js's picker, which Ctrl+Shift+P or the chevron's last row opens: settings.json's `prompts` and the slash commands and skills `claude_commands` lists. A pick is pasted into Claude's prompt to edit, with `{file}` as the file shown last and `{folder}` as the browser's folder. Text that matches nothing is sent as it is, or saved as a prompt.

### Claude tabs
- `terminal.js` runs one Claude tab: a `Term` (`term/view.js`), its PTY, the image-paste bridge, the `[Image #N]` links, the find bar's and jumps' keys, and the live resize.
  - `send` posts each key and size as it comes, and `early` holds what arrives before `pty_spawn` returns.
  - Output that holds a sixel or iTerm2 picture (`imageStart` in `sequences.js`) loads `term/images.js` first, and the output waits for it, in order.
  - In Claude's fullscreen view, a resize holds the last frame until Claude's redraw for that size is in (`refit`, `sized`, `release`), and the next size goes out once that frame shows, so a dragged edge reflows Claude as fast as Claude redraws. Claude never gets less than 20x6 (`MIN_COLS`, `MIN_ROWS`).
  - It returns `paste`, `prompt`, and `key`, through which nook puts text in the prompt as the user would.
- `term/` is nook's terminal. Its classes are xterm's (`.xterm`, `.xterm-screen`, `.xterm-rows`), which nook's CSS and benches use.
  - `vt.js` parses what the program writes and keeps the normal buffer with its scrollback and the alternate one, with no DOM. Its DECSET case ignores a lone mouse mode below the one in force (`RANK`). `windowOps` answers CSI 14 t and 16 t from view.js's `pixels()`. It counts resets (`resets`), so images.js sets its sixel palette back. On resize the normal buffer reflows wrapped lines, and on Linux rows that grow pull lines back from scrollback (`pull`), and on Windows the console sends blank rows instead.
  - `view.js` (`Term`) draws the screen as DOM rows and turns keys, the mouse, and the clipboard into what the program reads. `paint` rewrites only the rows whose cells changed since it last drew them, `palette()` writes a class per palette slot bound to its theme variable, and U+10EEEE (`PLACEHOLDER`) draws as a blank. A synchronized update holds a frame up to `SYNC_MAX_MS` (1 s), and a frame waits up to `BURST_MS` (8 ms) for a cursor hidden mid-frame, so an echo that arrives in pieces shows whole. `raise(r)` draws rows higher than their place, and the selection, marks, and pictures follow through `lift(y)`. `mapPoint` is the hook composer.js replaces. `mark` boxes cells over the text. On Linux, a selection sets PRIMARY and a middle click pastes it.
  - `keys.js` is what a key sends, `wcwidth.js` cell widths by Unicode 11, `urls.js` web addresses as links across wrapped rows, and `images.js` sixel and iTerm2 pictures, 32 MB of pixels a tab at most (`BUDGET`).
- `palette.js` maps palette slots to theme variables: 0-15 to `--ansi-*`, and each slot `mod/themes/nook.json` uses to `--claude-<token>` (`slotVar`). `cube(n)` is a slot's standard 256-color value, for view.js and images.js. `bytes` reads any CSS color as bytes through a canvas.
- `composer.js` paints a card over the prompt in Claude's fullscreen view: the draft rows in Claude's colors, the caret, a thumbnail for each `[Image #N]`, and the footer.
  - It finds the prompt between the last two full-width `─` rows, a rule with a label (a named session's) included, and hides when the screen stops matching that shape. `joint` joins Claude's rows into the lines the user typed, and the card wraps them at its own width.
  - The card sits on the terminal's bottom edge, measured on each resize, and `layout` moves the screen by the difference from Claude's prompt block, or while the transcript is short, only the rows under the lowest run of two or more blank rows above the prompt (`blanks`, `term.raise`). Its `mapPoint` reads a pointer over the raised rows as over the rows they are, so Claude's menus take clicks.
  - A click or drag on the card goes to the cell under the same character, and the card copies the selection Claude paints.
  - Its footer shows the model, effort, and a context ring from the report sessions.js hands it (`report`). The model and effort open menus, and a pick goes to the mod through `pty_command`. `report` also acts on a Run (pasted as Claude's `!` command, without Enter) or a Review (`nook-review`, which opens those files' changes) whose `at` is new.
- `pictures.js` paints the pictures Claude sends as kitty graphics: a command that names the file (t=f) or carries the picture as base64 (t=d, PNG or raw RGB(A) pixels, in chunks while m=1), then a box of U+10EEEE cells colored with the picture's id. The parser hands it each APC, in output order. It lays the picture over the box's cells, answers a query (a=q) with OK for t=d and t=f, and keeps the last 64 pictures sent whole as blob URLs.
  - A named `.mmd` file is a diagram the mod saved: `diagrams.js`, loaded with the first diagram, draws it as an SVG in the theme's colors, read at each render, as a background image, which runs no script. It holds `labels.js` (escaped, measured text), `layered.js` (layered layout), and a module per kind: `flowchart.js`, `sequence.js`, `classes.js`, `states.js`, `er.js`, `pie.js`, `gantt.js`, `mindmap.js`, `timeline.js` (and journey), and `gitgraph.js`. A diagram it can't read shows its source.
  - A named `.tex` file is a formula: `math.js`, loaded with the first formula, writes it as MathML Core through the DOM, which the webview lays out live in `--ink-1` (`math.css`). An unknown command shows in red, and a formula that doesn't parse shows its source.
  - A named `.pdf` is a PDF Claude read or a command saved: `pdfpage.js`, loaded with the first PDF, asks `pdf_page` for its first page at the box's pixel size.
  - A named `.html` or `.htm` file is a page Claude wrote. It shows in an `<iframe>` with an empty `sandbox`, laid out 1280 pixels wide and scaled into its box, with the mouse passing through to the terminal. Its URL keeps the file's folders (`pageUrl`), so what it links relatively loads from beside it, and it reloads when the session writes a new file in its folder or under it.
- `links.js` links paths in a Claude tab's text. On hover, `linkify.js` reads a row's candidates: paths in prose, grep and compiler output with `:line:col`, and the file of a tool call such as `Update(src/main.js)`. One `path_kinds` call asks which exist, under the tab's folder or the one a shell last reported in OSC 7, and answers hold for 3 s. Each that exists is underlined, an image previews, and Ctrl+click opens a file at its line, or a folder in the file browser. A line number in Claude's diff links to that line of the file the edit above it names. A row of a picture's cells links the file the picture names. `cells()` maps a row's text to its cells, for these links and `[Image #N]`. An OSC 8 link leaves nook only for http, https, and mailto (`WEB` in view.js).
- `peek.js` (and `peek.css`) is the card that shows when the mouse rests on a text file's path for 300 ms: twelve lines around the line named, numbered, colored by `highlight.js`. `peek_lines` reads only up to the last line shown and refuses a file with a NUL byte. `links.js` imports it on the first hover.
- `search.js` is a Claude tab's find bar (Ctrl+Shift+F), loaded the first time it opens. It finds matches in the buffer and marks them (`term.mark`), past 2,000 only the current one (`LIMIT`). In Claude's fullscreen view the terminal holds only the screen, so a step past the last match in view pages Claude's own view.
- `turns.js` jumps between the prompts you sent with Ctrl+Shift+Up and Down: Claude writes each prompt as ❯ and the text (> on Windows). On Claude's alternate screen, where the terminal keeps no history, a jump presses Claude's own Page Up or Page Down and reads the screen after each redraw. The prompt's row flashes (`term.mark`, gone after `FLASH_MS`).

### Files, editor, and git
- `files.js` is the file browser: history, breadcrumbs, pins, the Filter box, context menu, drag-to-prompt, and keys (Ctrl+Shift+E focuses it).
  - Every 2 s it reads the open folder's `file_stamp` and rereads the folder when that moves, for a few seconds after, and every 20 s. A folder of more than 400 entries keeps only the rows near the screen.
  - `order.js` sorts a listing in Explorer's order, an `Intl.Collator`'s with numeric ordering and case ignored, with printable-ASCII names compared by keys whose string order is the collator's.
  - `gitmarks.js` turns the git panel's status into each row's mark, so the browser runs no git of its own.
  - The context menu's file operations go through `shell.rs`, or `shell_unix.rs`. A drag onto a folder row, a pin, or a crumb calls `drop_files`. A folder with a `theme.css`, or a .zip `zip_holds_theme` finds one in, adds **Install theme**. A file Claude wrote in an open session has a dot, its folder a ring, and its menu **Claude's changes**.
- `viewer.js` is a file tab, or the settings drawer's `theme.css` editor: a picture, audio or video, a PDF, or text in the editor.
  - Markdown, CSV, TSV, SVG, and HTML with no `<script>` open rendered and toggle to their source. Markdown is `markdown.js`'s HTML (GitHub's flavor, as marked 18 writes it), judged by `Document.parseHTML` with `SANITIZE`, or by `sanitize.js` where the webview has no `parseHTML` (WebKitGTK). Both load with `highlight.js` on the first Markdown render.
  - `previews.js` holds every view besides Markdown and the editor, loaded the first time one opens: a picture that zooms around the pointer, SVG drawn from the editor's text in an `<img>`, HTML from the editor's text as an `<iframe sandbox>`'s `srcdoc` with a `<base>` beside the file, audio and video, PDF in the webview's own viewer, and a table (`delimited.js`) that keeps only the rows on screen.
  - It reads and writes one call at a time (`serial`). It rereads the file only after its stamp moves: without unsaved edits it takes the new text in place, and with them it keeps the edits and offers **Overwrite** or **Reload**. It saves with the file's own line ending (`eol`), through `write_text` over the text it last read.
  - Its change bars compare the editor's lines with git's copy (`git show :./name`), read when the file loads and whenever the index's stamp moves, through `linediff.js` (patience diff, then Myers between the lines found once in each). Alt+B toggles blame in the gutter (`blame.js`, from `git blame --porcelain`).
  - `outline()` asks `defs.rs`'s `outline` with the editor's text, or gives a rendered Markdown page's own headings.
- `editor.js` (`createEditor`, with `editor.css`) is the editor, loaded with the first file tab that holds text, or the drawer's `theme.css`. It draws only the rows near the viewport, keeps a height map only once wrapping or folds need one, lexes for at most 4 ms a draw, and lexes the rest when idle. Text past 2^24 device pixels across or down (`MAX_W`) scrolls scaled, and then `wheel` moves it as far as any text a notch. Its parts:
  - `doc.js` holds the text as lines, split at `\r\n`, `\r`, or `\n`, and `editor.text(eol)` joins them with the file's line ending.
  - `edits.js` holds the keys and commands (`keyName`), `find.js` the find panel, and `complete.js` completion from the language's keywords and the file's words. A file tab's editor has a status line: the caret, the language, the indent, the line ending, and wrap.
  - `highlight.js`, loaded with the first view that colors code, colors it as `tok-*` classes, by line-state lexers (`tokenize`, `highlight`, `lexLine`), for the editor, diffs, merges, peek, the drawer, and Markdown's code blocks. `langs.js`'s `lang(name)` is the one resolver of a language from a file name, an extension, or a fence's info string.
- `git.js` is the git panel: the repository of the active tab's folder or file, its changes with stage checkboxes, stashes, a merge or rebase in progress, the branch picker, sync with progress (`progress.js`), and the commit box. It polls every 2 s and paints a returning tab's last status at once. Writes run one at a time, so two never collide on the index lock.
- `diff.js` (and `diff.css`) is a diff tab, loaded the first time one opens: the staged and the unstaged changes, unified or side by side. A file's rows are built, then colored by `highlight.js`'s `tokenize`, only as the file nears the screen. A hunk's buttons, or s and d, stage, unstage, or discard the hunk or the lines picked in it by piping a patch (`patch.js`) to `git apply` through the panel's queue. The last discard can be put back.
- `merge.js` (and `merge.css`) is a conflicted file's tab, loaded the first time one opens: each conflict's sides next to each other, settled by taking one or both (`conflicts.js`), and **Mark resolved** stages the file.
- `history.js` (and `history.css`) is a history tab, of a repository or one file, loaded the first time one opens: `git log` in date order, 400 commits and then 3,000 at a time as the list nears its end, only the rows on screen built, laid out in lanes by `graph.js`. The commit picked shows its message and changes through `diff.js`. Its menu checks it out, branches from it, or cherry-picks or reverts it. A poll of the refs reloads it when a branch, tag, or HEAD moves.
- `proposal.js` shows an edit Claude asks a yes for (ide.rs's `openDiff`) with Accept and Reject, in `diff.css`'s look, loaded with the first one.
- `quickopen.js` (and `quickopen.css`) is quick open and the command palette, loaded on the first press. Typed text finds files through `index_files`, ranked by `fuzzy.js`, with `recent.js`'s files first. `>` runs a command from `commands.js`, `:` goes to a line, `@` lists the open file's outline, `#` finds definitions through `workspace_symbols`, and `%` finds text through `search_text`. F12 opens the definition of the word at the caret, and `main.js` keeps where each F12 was pressed for Alt+Left.
- `replace.js` (and `replace.css`) is the search tab, loaded on the first Ctrl+Shift+H, or Ctrl+Shift+F outside a Claude tab. It asks `find_in_files` after a pause in typing and replaces through `replace_in_files`, leaving out files with unsaved edits, and Undo calls `undo_replace`.

### Look
- `settings.js` is the gear's drawer. It applies nook's defaults, then the installed theme in use in `<style id="pack">`, then the user's `theme.css` in `<style id="theme">`.
  - It asks `read_theme` once a second while the page is visible, and when it becomes visible, and applies nothing on null. A relative `url()` in either `theme.css` names a file in its folder, and each URL carries the stamp, so a replaced picture or font loads again.
  - The drawer holds the theme cards, knobs (hue, accent, terminal, the wallpaper's strength and speed, both fonts, and both sizes), `theme.css` in a `viewer.js` editor that autosaves, nook's defaults read-only, settings.json's `command` and `gpu`, and GitHub sign-in. Once the editor exists, it applies every change, typed or from disk.
  - The font pickers list installed families through `queryLocalFonts()`, which WebKitGTK lacks, and a canvas width test keeps the terminal's list to monospace fonts.
- `themes.js` is the drawer's theme cards. Resting on a card previews its theme. **Install…** sends a .zip's bytes to `install_theme_zip`, a card's share button calls `save_theme_zip`, and **From a picture…** makes a theme with `themer.js` and sends its files to `install_theme_files`. With the system's light and dark matched, a pick is the theme for whichever the system shows (`dayTheme`, `nightTheme`). While Claude's colors follow the theme, a pick sets the `theme` key of `~/.claude/settings.json` to `custom:nook:nook` through `write_text`, over the text it read.
- `themer.js`, loaded with the first **From a picture…**, makes a theme from a picture: its palette in OKLab, the picture, a soft copy for the terminal, and a card, written as a `theme.css`. It encodes with `toDataURL`, since Chromium's `toBlob` waits up to a second for idle time.
- `backdrops.js` paints the gradients of body, `#pane`, `#files`, and `#git` from bitmaps, since software raster draws a dithered CSS gradient about five times slower than an image. Once an element's size has held still for `SETTLE_MS`, it bakes each gradient layer into a bitmap at that size, which paints in the gradient's place and stretches while the element resizes, until it bakes again. A restyle shows the live CSS until the new look bakes. Each bake is saved (`save_backdrop`), so the next start paints its first frame from it.
- `wallpaper.js` draws the living wallpaper on a canvas at the bottom of `#pane`, behind Claude tabs, and holds its picker, the titlebar's brush. theme.css names the scene in `--wallpaper` and colors each role with `--wallpaper-<role>`. The scene's last row ends at the top of the tallest composer card (`nook-card`). It draws ten frames a second, slower with `--wallpaper-speed`, and holds still while the pane resizes, while the window is hidden or unfocused, and with `--wallpaper-motion: working` while no session works. A frame that comes due while a key waits for its echo draws after the terminal paints (`nook-render`), or 50 ms after the key. Each frame copies glyphs from an atlas into only the cells that changed. Keeping a pick sets `--wallpaper` in the user's theme.css (`setVariable`).
- `wallpapers.js` holds the scenes (`SCENES`) and their color roles (`ROLES`). Each scene is a pure function of a grid's size and the time. It loads with the first scene other than none, the picker or the pointer reaching its button, or the palette.
- `style.css` is the layout of what the window opens with, and the `tok-*` colors. Each lazily loaded view brings its own sheet. `theme.css` holds the default for every color, font, and size, and declares Libron from `src/fonts`. Icons are Segoe Fluent Icons characters, and where that font isn't installed, `src/fonts/nook-icons.woff2` (`scripts/icons.mjs`) draws the same characters. Chrome text sizes are `rem` of `--ui-font-size`.

## Themes: `themes`
The themes nook ships, each a folder with a `theme.css`, a `screenshot.png` for its card, and the pictures it names. A theme's `theme.css` names where its pictures come from. `docs/themes.md` is the guide to making one.

## Data flow
A keystroke goes from view.js's key handling through `send` in terminal.js and `pty_write`, an Inline call, to the session's writer thread in pty.rs, then the console, the shell, and `claude`. Output comes back through the reader thread, the host `Stream`, host.js's `Channel`, and terminal.js into `term.write`, whose parser hands each APC to pictures.js.

Ctrl+V with no text on the clipboard pastes the paths of copied files: those Explorer's Copy or Cut put there, which `copied_paths` reads, on Linux those nook's file browser copied, or a file manager's `text/uri-list`. Claude attaches any picture among them. With no files, an image on the clipboard sends Claude Code's own image paste (Alt+V, or Ctrl+V on Linux), and Claude Code reads the clipboard itself. Claude saves the image to its temp folder, which nook's mod reports. Hovering `[Image #N]` asks `session_image` for that file and shows it from its file URL.

GitHub sign-in belongs to Git Credential Manager, which ships with Git for Windows. The settings drawer runs `git credential-manager github login`. GCM keeps the token and hands it to git for push and fetch, and nook sees only the account name.

## Rendering
WebView2 starts with `--disable-gpu` unless `settings.json` sets `"gpu": true`, beside `BROWSER_ARGS` in main.rs, which turn off Edge's out-of-process UI for pages and PDFs and SmartScreen. On Linux, `render_on_the_cpu_unless_gpu` sets `WEBKIT_DISABLE_COMPOSITING_MODE` and `WEBKIT_DISABLE_DMABUF_RENDERER` unless `gpu`. The UI then renders on the CPU, and typing latency holds steady while a training run saturates the GPU. Each terminal's screen is its own compositor layer, so a redraw rasters only its text and not the backdrop under it.

## Bench: `bench`
Every build a bench runs is nook as `dev.nook.bench` (`stats.mjs`). nook prints timings only when started with `NOOK_BENCH` set (`bench` in main.rs), and only then loads `src/bench.js`, and `main.js` marks its startup steps.
- `windows.mjs` (with `windows.ps1`) and `linux.mjs` (with `pixels.py`) are the benches README's **Build from source** runs. `tui.mjs` stands in for Claude's fullscreen view, `diffrepo.mjs` makes a repository with a large diff, and `gate.mjs` is `npm run gate`.
- `cdp.mjs` holds the command that starts a dev nook as `dev.nook.cdp` with CDP on 9222, and the session the CDP benches share. `ui.mjs` drags a panel's edge and types in Claude's prompt, and `resize.mjs` drags the window's corner and compares the baked backdrops with live CSS.
- `latency.ps1` times a key until the screen changes. `cpu_load.py` and `gpu_load.py` load every core and the GPU, as a training run does.
