# Architecture

Each launch of `nook.exe`, or `nook` on Linux, is one process with one window. The window's tabs hold Claude sessions and open files. Rust owns processes and the disk. The webview owns everything you see.

The installer runs `src-tauri/windows/hooks.nsh`, which adds Explorer's **Open with nook** for folders and folder backgrounds. Explorer starts `nook.exe "<folder>"`, and `dir_arg` in `main.rs` reads that argument. The uninstaller removes the menu entry.

## Rust: `src-tauri/src`
- `main.rs`: the window, `settings.json`, directory listing, reading, saving, and creating files, the `[Image #N]` lookup, and `run`, which starts every git and tar process. Every IPC command except the PTY, git, and shell ones lives here.
- `pty.rs`: one ConPTY per Claude tab through `portable-pty`, keyed by the id `pty_spawn` returns. A reader thread streams output to the tab over a `Channel` as raw bytes. When the shell exits, a waiter thread sends an empty chunk and the tab closes. `portable-pty` loads `conpty.dll` from beside `nook.exe` before Windows' own. nook ships it with its `OpenConsole.exe` from `src-tauri/conpty`, NuGet package `Microsoft.Windows.Console.ConPTY` 1.25.260930003. Windows' own ConPTY drops kitty graphics and sixel, and this one passes them through.
  `pty_spawn` appends nook's mod to `CLAUDE_CODE_PLUGIN_DIRS`, dropping the mod a nook it was started from added, points `NOOK_STATE` at the session's file in `%TEMP%\nook`, and sets `FORCE_HYPERLINK` so Claude sends OSC 8 links. It sets `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` too, so Claude draws a mod's `Image` as kitty graphics. Without it, Claude draws them only in kitty and Ghostty. `pty_state` reads that file, and `pty_command` leaves a request for the mod beside it.
- `git.rs`: the git panel's commands. Each runs the git CLI, so hooks, signing, and credential helpers behave as in a terminal. `git_status` finds the repository above any path and reads its status, line counts, and remotes in parallel. `git_diff` returns the staged or the unstaged changes as a unified diff, with untracked files written as git would diff them once added, so a patch of some of their lines stages them. `git` runs any other command.
- `pty.rs` on Linux opens a Unix pseudoterminal through the same `portable-pty` calls, and points the mod at `/tmp/claude-<uid>`, where Claude Code keeps pasted images, through `NOOK_CLAUDE_TEMP`.
- `shell.rs`: hands paths to the Windows shell. `open_path` runs a verb on a path: open, Open with, or Properties. `recycle`, `rename_path`, and `paste_files` run `SHFileOperationW`, so Explorer's progress, conflict, and error dialogs show, and Explorer can undo each change. They run on a blocking worker with no owner window, because a dialog that owned nook's window would disable it. `copy_files` and `paste_files` use the clipboard format Explorer uses for files, so a copy pastes in either app.
- `shell_unix.rs` stands in for `shell.rs` on Linux, with the same commands. `open_path` and `reveal` run `xdg-open`, `recycle` runs `gio trash`, and a rename never replaces a file. Desktops share no file clipboard the way Explorer's apps do, so Cut, Copy, and Paste keep nook's own, and a paste names a copy beside its original as Explorer does.
- `theme.rs`: themes. `read_theme` returns the user's `theme.css`, the installed theme `settings.json` names with its `theme.css`, and when a file beside either last changed. `install_theme` copies a folder, or unpacks a .zip with Windows' own `tar.exe`, or on Linux `unzip`, into a hidden folder in `themes`, then swaps it in with two renames. On first run, `read_theme` copies in the themes that ship with nook, from `themes` at the repository's root.
- `priority.rs`: every 2 s, sets above-normal priority on the typing path: nook, its WebView2 processes, the console host, the shell, and `claude.exe`. The walk stops at `claude.exe`, so the tools Claude runs keep normal priority. On Linux, `priority_unix.rs` does nothing, because raising a priority needs `CAP_SYS_NICE`.

## Claude Code mod: `src-tauri/mod`
A mod named `nook` that ships beside `nook.exe` and loads in every Claude session nook starts, beside the user's own plugins. Its hooks pass every event on unchanged. Its two `ui.render` hooks add an `Image` under Claude's own drawing: under a `Read` of an image or SVG and a `Write` of an SVG (`ToolUse`), under a shell command the pictures it wrote, three at most (picture files its command or output names, and new ones in the session's folder, each changed while it ran, which the `tool.call` hook on `Bash` finds once when the command ends), and under a prompt that names `[Image #N]` (`UserMessage`). Two more add how a shell command went, read from its output: a test runner's own counts (cargo, node's test runner, jest, vitest, pytest, mocha) and the first three tests that failed, the line that names a failure's error with a Rust error's `-->` place, what a build, install, linter, or git command says it did (a commit's hash and line counts, where a push went, a merge, cargo's warnings and errors, tsc's and eslint's counts, packages npm or pip added, npm's vulnerabilities), and how long a command past 3 s ran, which a `tool.call` hook on `Bash` times. Under a run of calls Claude folds into one line (`ToolGroup`, `Read 2 files, ran 1 shell command`) the files it read get one row first, relative to the session's folder and eight at most, so nook links each one, a search gets a row with its pattern and what it found (up to three files by name, else how many, or no matches), for a `Grep` or `Glob` and for a lone `grep`, `rg`, or `find` run through `Bash` that pipes into nothing, and each finished command with something to say gets a row of its own, six at most, and under a lone result (`ToolResult`) the one line. Each passes when the view is expanded, so ctrl+o shows Claude's own rows alone. They read the last 64 KB of output once per draw, in Claude's process, and nook's own code does nothing for them. The `Image` names the file, and its size in cells comes from the picture's pixel size, about 20 pixels a row. It writes the model, the `/model` aliases of the latest Fable, Opus, Sonnet, and Haiku, the effort and its five levels, and the context fill as JSON to `NOOK_STATE`. It also writes what the session is doing: `status` (working from `turn.start`, waiting while a permission prompt or a question to the user is up, idle from the main turn's `turn.complete`), `since`, the running tool as `activity`, the turn's first line as `prompt`, the subagents running, the turns finished, the session id, and `touched`, the files its Edit, Write, MultiEdit, and NotebookEdit calls wrote. `hooks/register.test.ts` checks those reports under `claude plugin test src-tauri/mod`. Every 250 ms it reads the model and the context fill, so a switch made any way and a `/clear` show, and runs a request that `pty_command` left in the `.cmd` file beside `NOOK_STATE`. A request runs only `/model` with one of the aliases or `/effort` with one of the five levels, through `$.command.run`, so the draft stays as typed. `claude plugin validate src-tauri/mod` lists everything it reads and calls.

The mod also ships a Claude theme, `themes/nook.json`, which `/theme` lists as nook and settings name `custom:nook:nook`. It draws each Claude color token it lists in its own palette slot from 16 up, on Claude's `dark-ansi` theme, so every other token takes one of the 16 ANSI colors. Each slot's stock xterm color is close to Claude's dark color for that token.

## Frontend: `src`
- `main.js` boots the window: settings, theme, file browser, tabs, and titlebar. Dragging a panel's edge sets `--files-width` or `--git-width` on `body` and saves it to `settings.json`. A double-click on the edge restores the theme's `--sidebar-width`. Each restyle sets the window's background to the theme's `--bg`, which shows while a growing window repaints.
- `settings.js` is the gear's drawer. It applies nook's defaults, then the installed theme in use in `<style id="pack">`, then the user's `theme.css` in `<style id="theme">`, reading both every second. The drawer holds the theme cards, knobs for `--h`, both fonts, and both sizes, `theme.css` in a `viewer.js` editor that autosaves, the bundled defaults read-only, `settings.json`'s `command` and `gpu`, and GitHub sign-in. A knob edits its declaration in the editor. Once the editor exists, it applies every change, typed or from disk. The font pickers list installed families through `queryLocalFonts()`, which `main.rs` grants. A canvas width test keeps the terminal's list to monospace fonts. A relative `url()` in either `theme.css` names a file in its folder. Each URL carries `read_theme`'s stamp, so a replaced picture or font loads again.
- `themes.js` is the drawer's theme cards. **Install…** sends a .zip's bytes to `install_theme_zip`, and the file browser's **Install theme** sends a path to `install_theme`. While Claude's colors follow the theme, a pick sets the `theme` key of `~/.claude/settings.json` to `custom:nook:nook` through `write_text`, over the text it read.
- `tabs.js` owns the tab strip and the pane under it. A tab is a Claude session, an open file, or a diff, and the window closes with its last tab. Closing a file with unsaved edits, or the window that holds one, asks whether to save. Ctrl+\ or a tab's **Open beside** splits the pane: the active tab keeps the focused half and the other shows in the other half, marked beside in the strip. A click in a half focuses it, a tab picked from the strip takes the focused half's place, and the divider drags.
- `sessions.js` follows every Claude tab's session. Once a second `pty_states` reads every tab's report in one IPC call, and `follow` turns each into the tab's mark: working, waiting on the user, or done, a turn that finished while the user looked elsewhere. A tab's dot shows its mark in its icon's place, the window's title counts the sessions waiting or done, and a session that starts waiting or finishes unwatched asks the taskbar for attention once. `sessions.test.js` checks `follow` under `npm test`.
- Reopening: `tabs.js` saves the Claude sessions open now (folder, session id, first prompt, which one showed) to settings.json's `sessions` as they change. The next start, unless it was asked for a folder or `reopenSessions` is false, reopens them as tabs that run `claude --resume <id>`. Only the tab that showed starts; each other one starts when it's first shown, so reopening many costs what opening one does.
- `launch.js` holds what the chevron beside + needs to start Claude other ways: continuing the folder's last session, resuming one of its saved sessions, which `history.rs`'s `claude_sessions` lists from the transcripts in `~/.claude/projects` (reading each one's first prompt and last title only), or starting in a git worktree of its own with `claude --worktree`. `claudeWith` adds Claude's flags to settings.json's command and refuses anything but names and ids. A session that moves, as into its worktree, reports its new root, and its tab takes the worktree's name and its git panel follows. `launch.test.js` checks it under `npm test`.
- `prompts.js` is quick prompts: Ctrl+Shift+P, or the chevron's last row, opens a picker of settings.json's `prompts` and the slash commands and skills Claude Code offers in the folder, which `commands.rs`'s `claude_commands` lists from `.claude/commands` and `.claude/skills` in the folder and its parents up to the git root, then `~/.claude`'s. A pick is pasted into Claude's prompt to edit, with `{file}` as the file shown last and `{folder}` as the browser's folder. Text that matches nothing is sent as it is, or saved as a prompt. `prompts.test.js` checks it under `npm test`.
- `dashboard.js` is the sessions dashboard, which the titlebar's Task View button or Ctrl+Shift+S opens over the pane: a card for each Claude tab with its mark and how long it has held it, its prompt, the tool it's running, its model, context, subagents, and the files Claude wrote. A click or Enter opens the tab, and each of a card's newest files opens its diff. It draws only while open, then once a second for its clocks.
- `palette.js` maps the terminal palette to theme variables: slots 0-15 to `--ansi-*`, and each slot `themes/nook.json` uses to `--claude-<token>`. `terminal.js` gives xterm those colors, and `composer.js` paints the card's text in them.
- `terminal.js` wraps xterm.js for one Claude tab: key handling, the ordered queue of keys and sizes, the image-paste bridge, the `[Image #N]` link provider, the live resize, `keepSameRows`, which keeps an unchanged row's nodes, and the mouse mode guard that keeps a drag alive. In Claude's fullscreen view, a resize holds xterm's last frame until Claude's redraw for that size is in, and the next size goes out once that frame shows, so a dragged edge reflows Claude as fast as Claude redraws. Claude never gets less than 20x6.
- `backdrops.js` holds the gradients of body, `#pane`, `#files`, and `#git` still while each resizes. Blink dithers every CSS gradient, and software raster draws one about five times slower than an image. Once an element's size settles, `bake` draws each of its gradient layers into a bitmap through an SVG `foreignObject`. While the element resizes, those bitmaps stretch in the gradients' place, and the live CSS returns after `SETTLE_MS`.
- `composer.js` paints a card over the prompt in Claude's fullscreen view. The card holds the draft rows in Claude's colors, the caret, a thumbnail for each `[Image #N]`, and the footer. It finds the prompt between the last two full-width `─` rows and hides when the screen stops matching that shape. Claude wraps the draft at `cols - 4` cells and drops the space it wraps at, so the card joins its rows back into the lines the user typed and wraps them at its own width, in one font size. The card is as tall as its content, sits on the terminal's bottom edge where composer.js measures it on each resize (CSS anchor positioning cost a whole-page layout per keystroke), and the screen moves by the difference from Claude's prompt block, so Claude's rows above the prompt, such as the slash menu, sit right above the card. A click or drag on the card goes to the cell under the same character, so Claude places its caret or selects, and Claude paints its selection as a background the card copies. Its footer adds the model, effort, and a context ring from the tab's `pty_state`, polled every 500 ms. The model and effort open menus, and a pick goes to the mod through `pty_command`. A rule with a label, such as a named session's, still counts as a rule, and the label shows beside the menus.
- `wallpapers.js` holds the living wallpapers' scenes. Each is a pure function of a grid's size and the time that sets characters and color roles in the grid's cells, so a frame is the same whenever it's drawn, and `wallpapers.test.js` checks every scene under `npm test` without a window. `paint` draws a grid on a canvas.
- `wallpaper.js` draws the wallpaper on a canvas at the bottom of `#pane`, under the tabs' views, behind Claude tabs only. theme.css names the scene in `--wallpaper` and colors each role with a `--wallpaper-<role>` variable, so a theme can ship a wallpaper and every window follows a pick. It draws ten frames a second, woken by a timer rather than every animation frame, holds still for 600 ms after each key or resize and while the window is hidden or unfocused, and draws one frame under reduced motion. Each character in each role's color is drawn once into a glyph atlas, and a frame copies tiles into only the cells that changed since the last frame, with the cell under each, since a glyph such as `_` reaches below its cell. The titlebar's brush opens the picker, a live thumbnail of each scene over the top of the pane. Keeping a pick sets `--wallpaper` in the user's theme.css through the settings drawer's `setVariable`. While no scene shows, the canvas keeps no bitmap. During a resize the last frame stretches, and it redraws at the new size once the size settles, as the backdrops do.
- `paths.js` holds what differs between Windows and Linux paths: the separator, roots, case, and which characters a name can't hold. Every module builds and compares paths through it, and `paths.test.js` checks both systems' rules on either one. `WINDOWS` also picks the image-paste key, Alt+V on Windows and Ctrl+V on Linux.
- `links.js` links paths in a Claude tab's text. On hover, `linkify.js` reads a row's candidates: paths in prose, grep and compiler output with `:line:col`, and the file of a tool call such as `Update(src/main.js)`. One `path_kinds` call asks which exist, under the tab's folder or the one a shell last reported in OSC 7, and answers hold for 3 s. Each that exists is underlined, an image previews, and Ctrl+click opens a file at its line through `viewer.js`'s `reveal`, or a folder in the file browser. A line number in Claude's diff links to that line of the file the edit above it names. An OSC 8 `file://` link opens in nook too, and the only other OSC 8 links that leave nook are http, https, and mailto. Nothing runs until the mouse rests on a row, and `linkify.test.js` checks the parsing under `npm test`.
- `pictures.js` paints the pictures Claude sends as kitty graphics: a command that names the file (t=f) or carries the picture itself as base64 (t=d, PNG or raw RGB(A) pixels, in chunks while m=1), then a box of U+10EEEE cells colored with the picture's id. `pictures.js` reads the commands from the raw output before `term.write`, lays the picture over the box's cells on screen, and hides the placeholder glyphs as xterm builds each row. It answers a query (a=q) with OK for t=d and t=f, as kitty does, and keeps the last 64 pictures sent whole as blob URLs.
- `peek.js` is the card that shows when the mouse rests on a text file's path in a Claude tab for 300 ms: the file's name, twelve lines around the line named (or its first lines), numbered, with that line marked and the hint to Ctrl+click. Rust's `peek_lines` reads only up to the last line shown and refuses a file with a NUL byte, which gets the name and hint alone. The lines take the editor's syntax colors once `editor.js` loads. `links.js` imports it on the first hover, so opening nook loads none of it.
- `search.js` is a Claude tab's find bar, opened with Ctrl+Shift+F. It loads `@xterm/addon-search` the first time it opens, marks every match in scrollback in the theme's selection color with the current one ringed in the accent, and counts them. Typing finds the match nearest the bottom, Enter and Shift+Enter step, and Esc closes it and clears the marks, after which the addon does no work.
- `turns.js` jumps between the prompts you sent in a Claude tab with Ctrl+Shift+Up and Down, or from the command palette. Claude writes each prompt into its history as ❯ and the text (> on Windows). A jump reads rows upward or downward from the view's top only when pressed, puts the prompt near the top, and flashes its row once with a decoration that removes itself.
- Sixel and iTerm2 pictures, as tools such as `img2sixel`, `chafa`, and `imgcat` draw them, go to xterm's image addon. It loads the first time `sequences.js` finds one in a tab's output, and that output waits until it and its sixel decoder are ready, so a tab that never shows one never loads it. Its pictures take at most 32 MB per tab. A tab answers CSI 14 t and CSI 16 t with its window and cell size in pixels, which picture tools use to size what they draw.
- `viewer.js` is a file tab, or the settings drawer's `theme.css` editor: an image, or text in the editor. Markdown, CSV, TSV, and SVG open rendered and toggle to their source. `previews.js` holds every view besides Markdown and the editor, and loads the first time one opens: a picture that zooms around the pointer, SVG drawn from the editor's text through a blob URL in an `<img>`, so it runs no script, audio and video, PDF in the webview's own viewer, and a table that keeps only the rows on screen in the DOM. `delimited.js` parses CSV and TSV as spreadsheets write them, and `delimited.test.js` checks it under `npm test`. Every 2 s the active tab reads its file's `file_stamp`, the change time and size, and rereads the file only after a change. Without unsaved edits, it takes the new text in place. With them, it keeps the edits and offers **Overwrite** or **Reload**. `write_text` writes only over the text the tab last read, so a save never silently replaces Claude's change.
- `editor.js` sets up CodeMirror for a file tab: the language its name implies, loaded on demand from `@codemirror/language-data`, the file's indent, the keymap, folding, and for code, closed brackets and completion from the language and the file's own words. A file tab's editor adds a status line, a CodeMirror panel that writes to the DOM only what changed. Markdown's code blocks use its highlighter too, and `style.css` colors both.
- `files.js` is the file browser: history, breadcrumbs, pins, context menu, drag-to-prompt, and a 2 s poll of the open folder. The poll reads the folder's change time through `file_stamp` and rereads the folder only when that moves, for a few seconds after, and every 20 s. A folder of more than 400 entries keeps only the rows near the screen in the list, between two spacers, so 100,000 files open as fast as 100. `order.js` sorts a listing in Explorer's order, the order of an `Intl.Collator` with numeric ordering that ignores case: a name of printable ASCII becomes a key whose plain string order is the collator's, so 50,000 names sort in about a quarter of the collator's time, and `order.test.js` checks the two agree. A folder with any other name is sorted by the collator. The poll compares a fresh listing with the last one as the disk gave it, before sorting, so an unchanged folder is never sorted again. The Filter box in the nav row narrows the shown rows to names holding its text; the folder's rows stay in `all`, and `items` is what's shown. Rows git counts as changed take its colors: `git.js` hands each new status the panel paints to `files.git`, and `gitmarks.js` turns it into a lookup from a path to its mark, folders above a change and everything in an untracked folder included, so the browser runs no git of its own. Hiding the git panel, which stops its polling, clears the colors. Ctrl+Shift+E, through `main.js`, focuses the list, whose own keydown handler moves a cursor row and runs Explorer's keys on it; the cursor is a path and an index into the folder's entries, so it survives redraws, and Escape blurs the list so focus returns to the tab. `list_dir` takes each entry's type from the listing itself, without a stat, except for symlinks. A click on a file opens it in a tab. The context menu of a listed file or folder starts with a row of icon buttons: Cut, Copy, Rename, and Delete, each through `shell.rs`. Rename, New file, and New folder put a name box in the row, and the poll holds still while it's open. Ctrl+click and Shift+click pick rows, and a drag or the menu acts on all of them. A drag that ends on a folder row, a pin, or a crumb calls `drop_files`, which moves the files, or copies them with Ctrl, through `SHFileOperation` on Windows so Explorer's undo and conflict dialog apply. An OS drop from Tauri's drag-drop event lands in the folder under the pointer the same way, as a copy. A folder with a `theme.css`, or a .zip that `zip_holds_theme` finds one in, adds **Install theme**. A file Claude wrote in any open session, as the sessions' reports list, has a dot, a folder that holds one has a ring, and the file's menu starts with **Claude's changes**, its diff from `git.js`'s `changes`.
- `git.js` is the git panel. It shows the repository that holds the active tab's folder or file: changes with stage checkboxes, the branch picker, sync, and the commit box. It polls that repository every 2 s and paints a returning tab's last status at once. Writes run one at a time, so two never collide on the index lock. The last commit's row, and a changed file's menu, open a history tab.
- `diff.js` is a diff tab, loaded the first time one opens. It shows the staged and the unstaged changes, unified or side by side. A file's rows are built, and then colored by `editor.js`'s `tokenize`, only as the file nears the screen, so a diff of thousands of lines opens at once. A hunk's buttons, or s and d, stage, unstage, or discard the hunk or the lines picked in it by piping a patch to `git apply` through the panel's queue. The last discard can be put back.
- `history.js` is a history tab, of a repository or one file, loaded the first time one opens. It reads `git log` in date order, children before parents, 400 commits and then 3,000 at a time as the list nears its end, and builds only the rows on screen. The commit picked shows its message and, through `diff.js`, its changes; its menu checks it out, branches from it, cherry-picks or reverts it through the panel's queue. A 2 s poll of the refs reloads it when a branch, tag, or HEAD moves.
- `graph.js` parses `git log` and lays the commits out in lanes, a page at a time, as the dots and lines `history.js` draws.
- `patch.js` parses git's diffs, builds the patch for part of a hunk, and finds the changed words between a removed line and the added line that replaced it. `patch.test.js` applies its patches with real git.
- `quickopen.js` is quick open and the command palette, loaded on the first press of Ctrl+P or F1, which `main.js` takes before Claude or the editor can. It lists the files of the active tab's folder through `index_files`, which `index.rs` answers with `git ls-files` inside a repository and a breadth-first walk outside one, capped at 200,000 files and four seconds. The first open builds the list, and later ones show the last list at once while a fresh one builds. `fuzzy.js` ranks them, and `fuzzy.test.js` checks it. `recent.js` keeps the files opened lately, which rank first. `commands.js` lists what the palette runs. After `%`, quick open asks `search.rs`'s `search_text` for lines holding the text, in the same file list: up to eight threads read the files, skipping binaries and files over 2 MB, and stop at 300 lines or three seconds. A query with a capital letter matches case exactly, and one without ignores it. A newer search stops an older one.
- `ui.js` holds the DOM helpers `$` and `el`, and the floating pieces: context menu, filtered picker, image preview, and drag ghost. A menu item that is itself a list of items renders as a row of icon buttons.
- `style.css` is layout only. `theme.css` holds the default for every color, font, and size, and declares Libron from `src/fonts`. Icons are Segoe Fluent Icons characters. Where that font isn't installed, `src/fonts/nook-icons.woff2`, which `scripts/icons.py` builds from Fluent UI System Icons, draws the same characters. Chrome text sizes are `rem` of `--ui-font-size`. The user's `theme.css` applies over both.

## Data flow
A keystroke goes from xterm's `onData` through its tab's ordered queue into ConPTY, then to the shell or `claude`. Output comes back through the reader thread and the `Channel`, past `pictures.js`, into `term.write`.

Ctrl+V with no text on the clipboard pastes the paths of copied files: those Explorer's Copy or Cut put there, which `copied_paths` reads, on Linux those nook's file browser copied, or a file manager's `text/uri-list`. Claude attaches any picture among them. With no files, an image on the clipboard sends Alt+V (`ESC v`), and Claude Code reads the clipboard itself. Claude saves the image to its temp folder, which nook's mod reports. Hovering `[Image #N]` asks `session_image` for that file and shows it through Tauri's asset protocol.

GitHub sign-in belongs to Git Credential Manager, which ships with Git for Windows. The settings drawer runs `git credential-manager github login`. GCM keeps the token and hands it to git for push and fetch, and nook sees only the account name.

## Rendering
WebView2 starts with `--disable-gpu` unless `settings.json` sets `"gpu": true`. The UI then renders on the CPU, and typing latency holds steady while a training run saturates the GPU. The scripts in `bench` measure it on Windows. `bench/linux.mjs` measures release builds on Linux, on its own Xvfb display, for each wallpaper given: open time and the steps of startup, resize time, a key's echo, a wheel step, a flood of output and the frames during it, idle and typing CPU, and memory before and after the flood fills the scrollback. With two builds it alternates their launches and flags what got worse. nook prints those timings only when started with `NOOK_BENCH` set, and only then loads `src/bench.js`; `main.js` marks its startup steps then too. Each terminal's screen is its own compositor layer, so a redraw rasters only its text and not the backdrop under it.
